# Command-line options

The game executable (`TheWarriors.exe` on Windows, `xbrun` on Linux) takes the game's
`default.xbe`, the extracted disc folder and then any number of options:

```text
TheWarriors.exe <disc>\default.xbe <disc> [options]
```

## Where to type them

- **Launcher:** Game page → **Extra arguments**. The text is added at the end of the command
  line exactly as typed (quote values that contain spaces).
- **Command line:** after `TheWarriors.exe <disc>\default.xbe <disc>`.

The launcher already passes most options from its own pages. Set those there instead of
repeating them in Extra arguments:

| Launcher page | Options it passes |
| --- | --- |
| Game | the game executable, the disc folder, `--hdd`, `--language`, `--texture-pack`, `--sound-pack`, `--spray-time`, `--no-text-fixes`, `--no-script-fixes`, `--skip-intro` (Skip intro videos, on in every preset), `--smart-allies` (Gameplay: Smarter allies, off in every preset), `--enemy-tactics` (Gameplay: Smarter enemies, off in every preset), `--mesh-pack` (the `characters-hd` folder, when it holds models) |
| Display | `--resolution` / `--render-scale`, `--widescreen`, `--fullscreen` (and `--no-refresh-match`), `--msaa`, `--aniso`, `--supersample`, `--fsr` (FSR 1 upscaling, off in every preset), `--sharpen`, `--bloom` (and `--bloom-strength`), `--rain-hd` (and `--rain-hd-puddles`, `--wet-light-streaks`, `--materials`), `--damp-streets`, `--neon-reflections`, `--reflections`, `--ssao` (and `--ssao-strength`), `--char-lighting`, `--world-lighting`, `--fire-light`, `--lamp-shadows`, `--world-shadows`, `--light-shafts` (and `--light-shafts-cheap`), `--volfog` (and `--volfog-quality`), `--contact-shadows`, `--lamp-lights` (and `--lamp-lights-strength`), `--level-lights` (and `--level-lights-max`), `--neon-glow` (and `--neon-glow-strength`, plus the `neon-masks` folder as a mask pack), `--normal-maps` (and `--normal-strength`, `--specular-strength`, `--normal-baked`; opt-in, off in every preset), `--dry-highlights` (and `--dry-highlights-strength`; with `--normal-maps`), `--parallax` (and `--parallax-depth`; with `--normal-maps`), `--filmic`, `--auto-exposure`, `--cutscene-dof`, `--sky-hd`, `--sharp-faces` (and `--sharp-faces-over-pack`, shown only with a texture pack; off in every preset), `--draw-distance` and `--prop-detail`, `--fx-scale`, `--no-movie-hd`, `--no-gamma-ramp` (Game's original brightness, on in every preset), `--soft-particles` (opt-in, off in every preset), `--fps-overlay` (On-screen counter, off in every preset; with `--fps-overlay-items` and `--fps-overlay-corner`), `--no-sharp-fonts` (only when Sharp text is off; on in every preset), `--shadow-scale`, `--shadow-soft`, `--shadow-range`, `--frames-in-flight`, `--present` (vsync on/off), `--sim60` (frame rate 60), the HUD style (`--hud-hd`, `--hud-hd-glass`, `--hud-glass` and the `--hud-hd-*` values) |
| Controls | `--button-icons`, `--pad-icons`, `--no-rumble`, `--pad-slot`, the button-icon pack (as a `--texture-pack`) |
| Options (advanced) | `--renderer`, `--present`, `--no-render-targets`, `--no-frame-blur`, `--audio`, `--video`, `--stats`, `--load-profile`, `--trace`, `--no-gpu-skinning`, `--no-gpu-vertex-programs`, `--no-direct-geometry`, `--no-frame-lock`, `--no-rate-fixes`, `--spawn-scale`, `--warp`, `--input-config` |

Extra arguments come last. For an option that takes one value, the last one given wins, so an
extra argument overrides the launcher's setting. `--texture-pack` adds a pack instead: the
launcher's packs come first and win where they have the same texture.

Invalid values print the usage text and exit with code 2.

## Display & quality

| Option | Default | Effect |
| --- | --- | --- |
| `--resolution WxH` | 640x480 | Render the 3D scene at the largest 4:3 size inside WxH (16:9 with `--widescreen`), e.g. `1920x1080` renders 1440x1080. Also the initial window size. |
| `--render-scale N` | 1 | Render at N x 640x480 (1-8). `--resolution` wins when both are given. |
| `--widescreen` | off | Report a 16:9 TV to the game: wider field of view and HUD layout, presented as 16:9. |
| `--fullscreen` | off | Start in desktop fullscreen. F11 or Alt+Enter toggles it while playing. |
| `--refresh-match` | on | In fullscreen, a screen whose refresh rate is not a multiple of 60 Hz (144, 165 Hz) is switched to its highest multiple of 60 at the same resolution (144 -> 120 Hz) so motion stays even. The switch happens once the first frame is on screen; if the game then shows no frame within 3 s (or gets minimized on its own) it goes back to desktop fullscreen for the session. The screen goes back at exit and while the game is minimized. `--no-refresh-match` keeps the screen's rate. |
| `--msaa N` | off | Multisample antialiasing, N samples per pixel (2, 4, 8; up to what the GPU supports). |
| `--aniso N` | off | Anisotropic texture filtering up to N (clamped to the GPU limit). |
| `--supersample N` | 1 (off) | Render at N x the size (2 or 4) and filter it down. Smooths every edge and texture; combines with `--msaa`. Costs N² x the pixels. |
| `--sharpen N` | 0 (off) | Contrast-adaptive sharpening of the finished frame, 0-100. |
| `--fsr MODE` | `off` | AMD FidelityFX Super Resolution 1, for GPUs that cannot hold 60 fps at the chosen size: the game renders below the output size (`--resolution` / `--render-scale`) and FSR upscales (EASU) and sharpens (RCAS) the frame to it. `ultra` renders at 1/1.3 of the size per axis, `quality` 1/1.5, `balanced` 1/1.7, `performance` 1/2 (e.g. `--resolution 1920x1080 --fsr quality` renders 960x720 and shows 1440x1080). Replaces `--supersample` and `--sharpen`: both are ignored, with a warning. The HUD and text are upscaled with the scene; `--fps-overlay`, the game's brightness ramp and `--dump-frame` are at the output size. |
| `--fsr-sharpness F` | 0.2 | RCAS sharpening of `--fsr`, in stops: 0 is the sharpest, each stop halves it, up to 2. |
| `--taa` | off | Temporal anti-aliasing: the 3D scene is shifted by a different sub-pixel offset every frame and blended with the previous frames, moved along with the camera, at the end of the 3D scene (before bloom, depth of field and the filmic look). Removes jagged and shimmering edges, including the ones `--msaa` misses (alpha-tested fences, wires, foliage, thin lamp posts), so `--msaa` can be lowered or turned off. The HUD, text, menus and movies are not affected. The history is dropped on camera cuts, when the cutscene bars appear or go, and after menus and loads. Characters moving fast against the camera can leave a short faint trail (motion comes from the camera only, for now). `--no-taa` turns it off. |
| `--taa-sharpness F` | auto | Left out: 0.5 for `--taa` and `--taa-upscale ultra`, rising with the render ratio to 0.85 at 2x per axis (`quality` 0.60, `balanced` 0.69, `performance` 0.85; with `--dynres` it follows the current size), since lower render sizes lose more fine detail (mission 7 still, fine detail against native 1080p + TAA: `balanced` 0.885 at 0.5 and 1.06 at 0.8, `performance` 0.825 at 0.5 and 1.12 at 0.9, no halos on the vest letters). Sharpening of the `--taa` / `--taa-upscale` result, 0 (none) to 1: RCAS, the robust contrast-adaptive sharpening of AMD FidelityFX FSR 1 (`taa_out.frag`), its lobe times F (1 = FSR 1 at 0 stops). It sharpens soft detail more than edges that already have high contrast and never pushes a channel past black or white, so a black and white edge is left as is (no halo). The accumulated history itself is never sharpened. 0.5 brings Quality's upscaled fine detail back to about native 1080p's; the launcher's "TAA sharpness" slider sets it. |
| `--taa-upscale MODE` | off | Temporal upscaling (FSR 2 style; implies `--taa`): the 3D scene renders below the output size and the TAA history rebuilds the output size from the jittered frames. `MODE` is `off`, `native` (1x: anti-aliasing only, below), `ultra` (1.3x per axis), `quality` (1.5x), `balanced` (1.7x) or `performance` (2x), or a ratio per axis from 1.1 to 3 (e.g. `1.4`); 1920x1080 `ultra` renders 1477x831, `quality` 1280x720. The frame is read with Catmull-Rom (anti-ringing) where it moves and the jittered samples nearest each output pixel build the still image; textures get the matching negative LOD bias log2(render / output) on top of `--aniso` (the startup line `[taa] temporal upscaling ...` prints both). Sharper than `--fsr` at the same render size once the camera settles (still images converge to near the full-size detail; fast motion is closer to `--fsr`). Bloom, wet ground, rain, the filmic look, the HUD, text, menus and movies stay at the output size. Textures get a matching negative LOD bias. Replaces `--fsr` and `--supersample` (ignored with a warning). Launcher presets: `quality` in Balanced, `ultra` in Quality, `balanced` in Integrated graphics. Cost (RTX 2060, 1920x1080, Quality preset effects, GPU ms per frame with `--stats`): hideout `quality` 5.9, `ultra` 6.5; mission 7 native 11.4, `quality` 7.5, `balanced` 7.3, `performance` 6.3 (`--fsr quality` 6.7). Fine detail against native 1080p + TAA (mission 7, still): `quality` 0.69 before the sharper resolve, 0.89 with it and the 0.5 sharpening, `ultra` 1.05 with `--aniso 16`. `native`: no upscaling, anti-aliasing only: the scene renders at the full output size and the same resolve (`taa_up.frag`, or `--upscaler fsr3`, FSR 3.1's "Native AA" ratio 1.0) keeps the jitter (8 positions), the history and the RCAS sharpening (auto 0.5), with no texture LOD bias; the startup line reads `[taa] temporal anti-aliasing native (...)`. With `--dynres` it is the ceiling the size drops from (see `--dynres`). Cost (RTX 2060, 1920x1080, the Quality effects without MSAA plus lamp shadows and medium fog, `[gpu-passes]` level window, ms per frame): mission 7 no AA 9.61, plain `--taa` 10.52, `native` 10.82 (resolve 0.80), `native --upscaler fsr3` 12.41 (FSR 3.1 passes 2.13 + output 0.13), `ultra --upscaler fsr3` 9.59; mission 8 (level81) `native` 6.63, `native --upscaler fsr3` 7.57, `ultra --upscaler fsr3` 6.34. An RTX 2050 is about 1.8x slower (the user's level81 log suggests up to 2.4x). Launcher: "Native (AA)" in the Temporal upscaling row. |
| `--upscaler taa\|fsr3` | taa | What rebuilds the output size under `--taa-upscale`: `taa`, our TAA resolve (`taa_up.frag`), or `fsr3`, a GLSL compute port of AMD FidelityFX FSR 3.1's upscaler (MIT; vendor-agnostic, FP32, Vulkan 1.0): dilated depth and motion, reconstructed previous depth and disocclusion, shading change and luma instability detection, thin-feature locks, Lanczos upsampling with a variance-box rectified history, then the same RCAS sharpening (`--taa-sharpness`) and output-size depth as `taa`. Motion vectors come from the camera reprojection and the character velocity pass; the reactive and transparency & composition masks from the scene's see-through draws (`--fsr3-masks`). Implies `--taa-upscale quality` when no mode is given; works with every mode, `--dynres` and `--frame-gen`. A device without storage-image atomics falls back to `taa` (the `[taa] temporal upscaling ... (TAA)` startup line says which runs). `--stats` adds `fsr3 ...` rows to `[gpu-passes]`. Launcher: "Temporal upscaler". |
| `--fsr3-masks on\|off` | on | FSR 3.1's two optional inputs, built from the frame's draws before the upscale: the 3D scene's see-through draws (blended, depth-tested, no depth writes, not characters) are drawn once more at the render size into an RGBA8 mask (`fsr3_mask.frag`, tested against the finished depth so hidden parts do not count). World particles (smoke, dust, fire, sparks, lamp halos and cones: the title's particle pass signature) and every additive layer go to the reactive mask (their contribution: an additive fragment's brightest channel, a blended one's alpha), which FSR dilates over 3 x 3, caps at 0.9 and uses as shading change (the history there is reset, so a moving or flickering layer leaves no trail); other alpha-blended layers (blob shadows, decals, sky layers) go to the transparency & composition mask at half weight, which tightens the history's colour box and drops locks there. With `--bloom` (every launcher preset) the title's particles, halos and fire come after the bloom split and so after the upscale, at the output size with no history: they never trail, and the masks only cover the few blended layers before it (2-10 draws a frame in missions 7 and 14); without `--bloom` the particles come before the upscale and the reactive mask matters. An opaque-only frame leaves both masks zero and upscales byte for byte as with `off`. `off`: FSR 3.1 without them (before / after comparisons). `--stats` adds an `fsr3 masks` row to `[gpu-passes]`; the log prints `[fsr3] masks: ...` when a frame has more mask draws than any before it. |
| `--taa-lite auto\|on\|off` | auto | A cheaper `--taa-upscale` resolve for integrated GPUs: the same blend of the frame and the history from 22 texture reads per output pixel instead of 48 (a 6-pixel neighbourhood for the colour box, the frame's Catmull-Rom folded into 5 filtered reads, gathers for the depths and the history distances). `auto` uses it on an integrated GPU only (Intel Iris Xe and UHD, AMD APUs), `on` always, `off` never. A little softer on fine moving detail; the still picture, the depth written back for the passes after it and the rain stripes fix are kept. Not with `--msaa` (the full resolve runs) or `--upscaler fsr3`. The log says `[taa] lite upscale resolve` when it is in use. |
| `--dynres TARGET_MS\|auto` | off | Dynamic resolution: with temporal upscaling (implies `--taa-upscale ultra` when no mode is given) the 3D scene's render size follows the GPU time of each frame (Vulkan timestamps) to keep it under `TARGET_MS` (4-100; `auto` = 14 ms, a 60 fps frame with headroom for the CPU side and clock changes). Over the target it drops at once to the size the pixel count predicts (two frames in a row over it, aiming at 92 %); with 20 % room for half a second it rises by at most 4 % of the output size per step; after a change 4 frames are ignored (their timestamps still describe the old size). It never goes above the `--taa-upscale` mode's size (the quality ceiling) nor below 1 / `--dynres-min` of the output. The TAA history stays at the output size, so a change shows no seam (the texture LOD bias stays the starting size's). `--stats` prints a `[dynres] render WxH` line per change; the startup line `[dynres] dynamic resolution: GPU target ...` gives the range. With `--taa-upscale native` it starts at the output size, `auto` is 15.5 ms (93 % of a 60 fps frame, so the full size is kept as long as the GPU makes the frame) and the floor is `ultra`'s 1.3 per axis unless `--dynres-min` is given. Hysteresis: a drop needs two frames over 15.5 ms, a rise half a second under 12.4 ms (80 %) and goes up at most 4 %, which costs about 8.5 % more GPU time (13.5 ms from 12.4), still under the drop line, so it does not flap; a drop right after a rise doubles the wait before the next rise (up to 16x). Launcher: "Dynamic resolution (hold 60 fps)". `--no-dynres` turns it off. |
| `--dynres-min RATIO` | 2 | With `--dynres`: the lowest render size as a ratio per axis, 1.1 to 3 (2 = a quarter of the output's pixels, FSR 2's performance). Under `--taa-upscale native` the default is `ultra`'s 1.3. |
| `--vrs off\|auto\|quality\|performance` | off | Variable rate shading (VK_KHR_fragment_shading_rate with attachment rates, e.g. NVIDIA RTX / GTX 16, AMD RX 6000 and newer). At the end of every frame a small compute pass (`vrs_rate.comp`, written after the approach of AMD FidelityFX Variable Shading) measures, per 16 x 16-pixel tile of the frame just drawn, the luminance steps between neighbouring pixels along x and along y (a mix of the tile's mean step and its largest one) and the change of the tile's mean luminance since the previous frame; the next frame's world draws are shaded at 2x1, 1x2 or 2x2 (`performance`: up to 4x4, 4x2, 2x4 without temporal upscaling) where a direction's steps stay under the cutoff (raised by up to 2x by the temporal change: moving or flickering content). The frame is measured after fog, depth of field and TAA, so fogged and blurred parts count as flat. Always at 1x1: characters (GPU-skinned, character-lit or flagged), alpha-tested draws (fences, wires, foliage), emissive draws (neon signs), draws without depth test (HUD, text, menus, movies) and everything after the TAA op. Each frame an eighth of the tiles is forced to 1x1 (a moving pattern), so detail a coarse rate had hidden is measured again within 8 frames. With `--taa-upscale` / `--dynres` the coarsest rate is 2x2. `auto` = `quality` where supported, off on Intel GPUs; unsupported: off with a `[vrs] off: ...` startup line (else `[vrs] variable rate shading quality: 16x16 tiles, up to 2x2`). `--stats` adds a `vrs rate image` row to `[gpu-passes]`. Cost and gain (RTX 2060, 1920x1080, Quality preset effects without `--dynres`, `[gpu-passes]` scene draws off -> `quality`, last 600-frame window): mission 7 street 2.18 -> 1.92 ms, hideout 2.27 -> 1.77, rain (m10:2) 2.18 -> 1.73, mission 8 1.17 -> 1.04; the rate pass 0.07-0.09 ms; native 1080p (Ultra) mission 7 2.90 -> 2.44; Balanced (720p, no MSAA) 1.17 -> 1.09, under the rate pass's 0.10. An RTX 2050 (about 1.8x slower) is estimated at 0.3-0.8 ms saved net in Quality. `performance` gains nothing more under temporal upscaling (2x2 cap). Launcher presets: on in Quality and Ultra, off in Performance and Balanced. Launcher: "Variable rate shading (VRS)". |
| `--bench` | off | Benchmark: the menus are pressed through (`--skip-intro` and the headless input script; on a fresh save it starts a new game), the first level load goes to mission 7's street (`--warp 7` unless `--warp` is given; the warp blocks every save write, so the save on disk never changes), and after 10 s of play the camera pans (right stick held) for 3600 frames (60 s at 60 fps). Then a short report goes to the log (`[bench]` lines) and to `--bench-out` and the game exits: average and 1 % low fps (the mean of the slowest 1 % of frame times), the worst frame, GPU ms per frame and per pass (the `--stats` pass list), render size (range with `--dynres`), GPU name and driver, and the settings without file paths. A load during the window starts it again; no level after 30000 frames writes a failure report. Launcher: "Run benchmark" on the Display page. |
| `--bench-out FILE` | bench-report.txt | With `--bench`: the report file (the launcher writes `logs/bench-<profile>-<time>.txt`). |
| `--frame-gen` | off | Frame generation: a frame half way between every two real frames, shown one display refresh before the real one, so a 120 Hz screen shows 120 frames a second from the 60 Hz game. At the end of the 3D scene and its effects (before the HUD) the frame target is copied and a motion field is written at the display size (the camera's reprojection from depth, as `--taa`; skinned characters' own motion when `--taa` draws their velocity). The HUD is what the frame gains from there until the full-screen tint and frame-feedback blur the title draws over everything at the end: those pixels keep the new frame's. The generated frame moves every other pixel of the new frame half way back along its motion (the nearest surface wins; holes take the farthest surface around them), reads both shown frames along it (dropping a side where a nearer surface, the HUD or the cinema bars cover it) and blends them, or keeps the new frame where they disagree strongly (rain, sparks, flicker: what has no motion vectors). Menus, movies, camera cuts, the first frame after a load and the frame where the cutscene bars appear or go are not interpolated. The generated frames are shown only in a window (not with `--dump-frame` or `--present readback`) on a display at 120 Hz (or 240) with `--sim60`: fullscreen with `--refresh-match` switches a 144/165 Hz screen to 120 Hz; at another rate the frames are shown as without it. They pause while the game runs under 60 fps for 2 s and resume after 2 s at 60, then after 4, 8, 16 and at most 32 s at 60 for each further pause (forgotten after a minute shown; `[frame-gen]` lines); while paused the real frame is presented twice, so the pacing does not change. Presentation becomes FIFO with two more swapchain images (two presents a frame, a refresh apart; `--present` is ignored). Where the driver has VK_KHR_present_wait, frames are paced by present completion: before a frame takes its images the renderer waits until the real frame before the last one is on screen (at most one frame's pair queued, one more swapchain image), so the waits follow the display instead of filling the queue; the log then reports the display's measured rate (`[frame-gen] pacing by present completion: ...`), else `[frame-gen] pacing: no present waits on this driver`. The motion field takes the nearest depth of the 3 x 3 render pixels around each pixel when the scene is jittered (TAA) or resampled, so the soft edges of a character do not move with the background behind it. About 10 ms more input latency (the real frame waits half a frame). With `--dump-frame` and `--dump-every N` each dumped frame also writes the frame before it and the generated frame between them (`<path>.N-g.bmp`). `--no-frame-gen` turns it off. Needs a sampled depth target and R32 storage-image atomics (Vulkan 1.0); otherwise `[frame-gen] unavailable` and frames as without it. Cost (RTX 2060, 1920x1080, Quality preset argv, mission 7 street, `[gpu-passes]` with `--stats`, another headless run sharing the GPU): about 1.6 ms per generated frame (the motion field, the HUD mask, the splat and the interpolation at the display size, three copies); an RTX 2050 laptop, about a third of the bandwidth, is estimated at 4-5 ms, so the real frame must stay under about 12 ms there for 120 fps. Off in every launcher preset; the launcher shows its toggle only on screens with a 120 Hz or faster mode. |
| `--frame-gen-of` | off | `--frame-gen` plus optical flow: where the two frames disagree along the motion vectors (rain, sparks, flicker, glows: what has none), the motion found by matching 16 x 16 blocks of the two HUD-less frames (half-resolution luma, up to 12 pixels a frame each way, still areas preferred) is tried, and both frames are blended along it when they agree there; otherwise the new frame's pixel is kept as without it. About 0.35 ms more than `--frame-gen` on the RTX 2060 at 1920x1080 (1.9 ms in all); RTX 2050 estimate about 1 ms more. Implies `--frame-gen`. |
| `--anim-interp` | off | Smooth animation in the 30 FPS mode: without `--sim60` the game changes characters, objects and the camera every other frame; with this flag each draw is shown between its last two states (the character skinning matrices and the world-to-clip matrix lerped, the TAA camera alike), so the scene moves on every display frame, one display frame (16.7 ms) later. Camera cuts and animation snaps (a bone moving more than 2 units or turning more than 90 degrees between states) are shown as they are. GPU vertex-program draws only (`--gpu-vertex-programs`, the default: nearly the whole 3D scene). With `--sim60` everything already changes every frame and almost nothing is blended. `--no-anim-interp` turns it off. With `--stats`, `[anim]` lines report how often character poses, objects and the camera change as shown. |
| `--fps-overlay` | off | A small frame counter in a corner, for example `60 FPS  16.6 ms`: presented frames per second and the mean frame time, averaged over half a second. Drawn last, over the finished image (after bloom, the cinematic look and sharpening), at the window's own pixels. Almost free. `--no-fps-overlay` turns it off again. |
| `--fps-overlay-corner C` | `tl` | Corner of `--fps-overlay`: `tl` (top left), `tr`, `bl` or `br`. |
| `--fps-overlay-items LIST` | `fps,ms` | What `--fps-overlay` shows: any of `fps`, `ms`, `cpu`, `gpu`, comma separated, always shown in that order, for example `60 FPS  16.6 ms  CPU 34%  GPU 71%`. `cpu`: this game process's CPU use over the same half second, where 100% means every logical core of the machine is busy (so one fully busy thread on a 12-thread CPU reads 8%). `gpu`: the game's own GPU work per frame (Vulkan timestamps around each frame's commands) over the frame period; it is not the whole GPU's utilization (other programs, the compositor and the copy to the window are not counted), and it reads `GPU --` when the GPU has no timestamps. It only chooses the items: `--fps-overlay` turns the counter on. |
| `--bloom` | off | Light bleeds from street lamps, neon, fire and the game's glow sprites into the 3D scene. The HUD and text are drawn after it and do not glow, and neither do the lamps' own halo and light-cone sprites (they already are the glow and look as without bloom). `--no-bloom` turns it off again. |
| `--bloom-strength F` | 0.6 | How much glow `--bloom` adds, 0.1-3. |
| `--bloom-threshold F` | 0.75 | How bright a pixel must be to glow with `--bloom`, 0-1 (lower: more of the scene glows). Fire, neon and flares glow from about four fifths of it. |
| `--rain-hd` | off | Better rain: while it rains, the game's flat rain overlay is replaced by thin falling streaks at several distances. Walls, cars and people in front of the camera hide the streaks behind them (the see-through parts of fences and wire do not), near streaks are longer, wider, fainter and faster than far ones, the streaks catch the scene's light (brighter near lamps, faint in the dark), and the slant, speed and colour follow the game's own rain. The HUD is drawn over the rain (a see-through minimap shows it behind). When the game starts or stops its rain (for example when the player walks into or out of a building), the streaks, splashes and wet ground fade in or out over half a second of game time instead of appearing or vanishing at once. Without rain nothing changes. `--no-rain-hd` turns it off again. |
| `--rain-hd-density F` | 1 | How many streaks and splashes `--rain-hd` draws, 0.25-4 (times the game's own amount, which changes as the rain grows). |
| `--rain-hd-splash` | on | With `--rain-hd`: drops landing on the ground show tiny splashes (two or three droplets thrown up for a moment) and, on flat ground, rings that widen and fade. Only on surfaces that face up (streets, car roofs, crate tops), never on walls, people or the HUD; they catch the scene's light (clear near lamps, faint in the dark), fade with distance and stay in place on the ground when the camera moves. The game's own few splashes are kept. Ground under a roof gets none (see `--rain-hd-cover`). `--no-rain-hd-splash` keeps the streaks without them. |
| `--rain-hd-wet` | on | With `--rain-hd`, while it rains: the ground looks wet. Surfaces that face up (streets, pavements, car roofs) get a little darker and glossy and reflect the bright parts of the scene (street lamps and their halos, lit windows, signs, car lights) as soft, vertically smeared reflections, stronger at grazing angles, fading towards the screen edges. ## Photo mode

Photo mode is always available in the game: **F9** (unless F9 is bound in your input settings) or **Back + RB** held for half a second freezes the game, hides the HUD and frees the camera; **A** saves a PNG in the `Photos` folder next to the game, the adjustments panel (resolution up to 4K, supersampling, samples, depth of field, exposure, colour filter, saturation, vignette, grain, cinema bars, characters) opens on entry; **Y** or **B** (keyboard **E** or **F**) hides it so you see the whole picture, with nothing else drawn over it after a 2-second "Y (E): show panel" hint, and **Y** (**E**) shows it again; with the panel hidden, **B** / **Backspace** (Back) / **Escape** / **F9** leaves and puts every setting back.

| Option | Default | What it does |
| --- | --- | --- |
| `--photo-dir DIR` | `Photos` next to the game | Folder for the photos (created when missing). |
| `--photo-prepare` / `--no-photo-prepare` | on | Also builds the renderer passes photo mode switches on (ambient occlusion with bounce light, contact shadows, volumetric fog, sun shadows) at their highest quality when they are off in play. They stay off while you play (no frame-time cost) but take some video memory; `--no-photo-prepare` leaves photo mode with only the effects your settings already use. |

| `--ai-debug` | off | Log the player's crew AI: `[ai]` lines when a crew member or a character fighting the crew changes goal, action or target, and every 10 s of game time each crew member's time near an enemy without engaging, damage dealt and hits taken, plus how the attack gate answered the crew; `[tactics]` lines every 10 s with the enemies' attack decisions on the player and on the crew, the attack ids they picked against the player (split by whether the player stood still) and the player's hits and damage taken. Diagnostic: it routes three game calls (the Fight goal's attack gate and its two attack choices) through counters; behaviour is unchanged. |
| `--combat-debug` | off | Combat viewer for development: draws every character's hurt volumes (green), strike volumes while an attack is active (red), weapon spheres (orange) and recent contacts (yellow) over the picture, and logs `[combat]` lines: each strike window with its hit tests, sweep and closest approach to every other character, each move's startup / active / recovery frames, contacts and damage. Works headless through the log. |
| `--rate-probe FILE[:MS]` | off | Every MS ms (default 100) of game time, snapshot the game's data section into FILE, for `tools/ratediff`. |
| `--rate-probe-range ADDR:SIZE` | none | With `--rate-probe`: one more memory range to snapshot, or `@PTR[+OFF]:SIZE` behind a pointer. Repeatable. |
| `--poke ADDR:HEX[/EXPECT]` | none | Write bytes into game memory before it starts; with `/EXPECT` only when the original bytes match (otherwise exit 2). Repeatable. |
| `--watchdog SEC` | off | After SEC seconds, print every game thread's position and exit with code 4. |
| `--win-thread-probe` | off | Print thread diagnostics at startup phases. |
| `--symbols FILE` | none | Symbol file (`LIB__Name = 0xADDR` lines): names in crash reports and for `--hook`/`--skip`. |
| `--hook SYMBOL\|0xADDR` | see below | Success hook: report and exit when the game reaches it. Repeatable. |
| `--skip SYMBOL:POPBYTES[:RET]` | none | Patch a game function to return RET immediately. Needs `--symbols`. Repeatable. |
| `--no-hle-d3d` | off | Do not replace the graphics entry points; stop at the hook instead (default hook `D3D8__Direct3D_CreateDevice`, needs `--symbols`). |
| `--no-hle-audio` | off | Do not replace the audio entry points (the game then faults). |
| `--no-hle-input` | off | Do not replace the input entry points (the game sees no controller). |
| `--no-default-skips` | off | With `--no-hle-input`, do not skip the USB start-up function. |
| `--fake-mmio` | off | Experimental: back some console hardware registers with memory. |
| `--patch-fs` | off (always on Windows) | Rewrite the game's thread-block accesses as the Windows build does (Linux: for testing). |
